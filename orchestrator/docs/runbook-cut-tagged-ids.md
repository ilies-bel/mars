# Runbook: Hard Cut to 4-Letter Tagged IDs

**Purpose:** One-time operator procedure to switch every Mars-generated id to
the tagged form `<kind>-<hex>` (for example `task-a1b2c3d4`, `prop-9f8e7d6c`).
The cut is destructive: per-repo state databases are wiped and in-flight work is
drained or purged before the new binary ships. No migration or backfill is
performed.

**ADR references:**
- `docs/adr/0039` — Stored 4-letter id tag supersedes ADR-0010 bare-hex identity
- `docs/adr/0010` — Id-format migration orphans in-flight worktrees

---

## Gate command

After each phase run the gate check:

```sh
mars cut verify <phase>
```

`<phase>` is one of `drain`, `reset`, or `recreate`. Exit code 0 means the
gate is clean — proceed to the next phase. Any non-zero exit means the check
listed one or more unresolved items; fix them and re-run before continuing.

---

## Preconditions

Before starting the cut, confirm all of the following:

1. The *new* Mars binary (the one that generates tagged ids) is available or
   will be installed in Phase 2.
2. You have write access to the target repo's `.mars/` directory.
3. No other operators are running the Mars daemon on the same repo.
4. Run the initial gate check to see what in-flight work remains:

   ```sh
   mars cut verify drain
   ```

   If exit 0, skip directly to Phase 2. Otherwise, proceed with Phase 1.

---

## Phase 1 — Drain in-flight work

**Goal:** reach a state where no tasks are `queued`, `blocked`, or `running`.

1. List in-flight tasks:

   ```sh
   mars list --status queued,blocked,running
   ```

2. For each task shown, either:
   - Wait for it to complete naturally (preferred for tasks that are already
     `running`), or
   - Abandon it permanently:

     ```sh
     mars purge <task-id>
     ```

   Repeat until the list is empty.

3. Stop the daemon so no new work is dispatched while you complete the cut:

   ```sh
   mars daemon stop
   ```

4. **Gate check — drain:**

   ```sh
   mars cut verify drain
   ```

   Exit 0 confirms no in-flight tasks remain. Fix any listed items and re-run
   until clean before continuing.

---

## Phase 2 — Ship the new binary

**Goal:** ensure the active `mars` binary generates tagged ids.

1. Install the new binary. For production consumers use the one-liner bootstrap:

   ```sh
   curl -sSL https://github.com/<org>/mars-framework/releases/latest/download/get-mars.sh | bash
   ```

   For a dev install from a clone of the framework:

   ```sh
   cd /path/to/mars-framework
   ./install.sh
   ```

2. Confirm the installed binary is the expected version:

   ```sh
   mars --version
   ```

3. **Gate check — drain (re-confirm with new binary):**

   ```sh
   mars cut verify drain
   ```

   Re-confirms the drain is still clean after the binary swap. Exit 0 to
   proceed.

---

## Phase 3 — Reset the per-repo state databases

**Goal:** wipe all pre-cut rows so the fresh binary starts from a completely
clean slate.

> **Database file note.**
> The live Mars database is `.mars/mars.db` — the single consolidated store
> for tasks, proposals, and all related tables. The older split files
> `.mars/queue.db` and `.mars/state.db` are stale pre-merge artifacts; if
> they exist on disk they are typically 0-byte placeholders and hold no live
> data. Delete them for tidiness, but the operative reset is `.mars/mars.db`.

1. Confirm the daemon is stopped:

   ```sh
   mars daemon status
   ```

   If it is still running:

   ```sh
   mars daemon stop
   ```

2. Delete the database files, stale worktrees, and lock/port files:

   ```sh
   rm -f .mars/mars.db .mars/queue.db .mars/state.db
   rm -rf .mars/worktrees/
   rm -f .mars/.merge.lock .mars/http.port
   ```

3. Re-initialise the database under the new tagged-id schema:

   ```sh
   mars init
   ```

4. **Gate check — reset:**

   ```sh
   mars cut verify reset
   ```

   Exit 0 confirms every entity table has zero rows. If non-zero, the output
   lists each non-empty table and its row count. Delete `.mars/mars.db` and
   re-run `mars init`, then re-run the gate check.

### Gate check — recreate

After re-creating all seven proposals:

```sh
mars cut verify recreate
```

This prints a carry-forward checklist with ✓ for each found title and ✗ for
each missing one, then exits 0 only when no forbidden ids are present. Re-enter
any ✗ proposals and re-run until the checklist is all ✓ and the exit code is 0.

## Final eyeball check

After all gate checks pass, do a visual sweep to confirm every entity in the
live databases now carries a tagged id:

```sh
mars list
mars proposal list
mars inbox list
```

Every id shown should read `<kind>-<hex>` (for example `task-a1b2c3d4`,
`prop-9f8e7d6c`). If any bare-hex ids (eight hex digits, no prefix) or legacy
`mars-<hex>` ids appear, stop and investigate before treating the cut as
complete — the new binary may not be active or `mars init` may not have
applied the correct schema.

---

## Recovery

If the procedure fails at any phase, resume from that phase rather than
restarting from the beginning:

| Phase failed | Recovery action |
| ------------ | --------------- |
| **Phase 1 — drain** | Purge or wait for remaining in-flight tasks, then re-run the drain gate check. |
| **Phase 2 — ship** | Re-run the install command, confirm `mars --version`, then re-run the drain gate check with the new binary. |
| **Phase 3 — reset** | Delete `.mars/mars.db` again and re-run `mars init`, then re-run the reset gate check. |
| **Phase 4 — recreate** | Run `mars proposal list` to see what was already entered; re-enter only the missing titles, then re-run the recreate gate check. |

Do not attempt to migrate or backfill pre-cut ids. Any entity not explicitly
re-created in Phase 4 is intentionally gone. That is the hard-cut contract.
