# Non-attachable node-pty Runtime supersedes ADR-0013 tmux; goal is provider-agnostic execution under each agent's native interactive harness

Context: ADR-0013 introduced a non-headless Runtime backed by tmux for an attachable pane. That backend never shipped (exploratory branch). The real goal is provider agnosticism: drive any agent CLI (claude, codex, gemini, ...) under its native interactive TTY harness rather than the restricted 'claude -p' print mode. Decision: retire ADR-0013's tmux backend entirely (no tmux dependency, no attach). The non-headless Runtime is 'pty' — the agent runs under a non-attachable node-pty so it gets the exact harness a real interactive user gets; Mars feeds the prompt and captures output to traces/logs. There is no human-attach: the operator reads traces/logs after the fact, not a live stream. Why supersede rather than add a third value: carrying a never-built 'tmux' value beside 'pty' contradicts the no-backwards-compat rule. tmux was rejected because it forces a consumer-machine dependency the standalone mars binary cannot assume, and because attach was never the goal. Provider is a separate Worker axis from Runtime (which agent vs how it executes).
