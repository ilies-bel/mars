# Task acquiring a blocker mid-run short-circuits to blocked before verify

A coder may file a self-unblock follow-up via 'mars task add --blocks $TASK_ID' when it cannot finish (fix-attempt cap, read/grep budget, architectural deferral). The edge written is (current task waits on new task) — the inverse of --blocked-by. After the agent exits, the implement workflow checks whether the current task acquired any unresolved blocker during its run; if so it routes the task to 'blocked' and skips verify and merge, rather than verifying known-partial work. The existing onBlockerTaskCompleted path re-queues it once the follow-up reaches done. Trade-off: we give up the simplicity of 'verify always runs after the agent' to make the brief's long-standing 'commit partial work, exit, get re-dispatched' promise actually true; previously the brief told coders to use --blocked-by $TASK_ID, which wrote the backwards edge and never re-dispatched the parent.
