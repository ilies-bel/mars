# Steward autonomy boundary: runtime knobs autonomous, workflow-code diff-for-validation

The Steward is an event-driven subagent (spawned by the orchestrator on degraded KPIs, resource-load spikes, or onboarding) that tunes the framework. Its authority splits by reversibility and file ownership: it changes runtime operating parameters (worker count, budgets, schedules, recovery kill-switch) autonomously and narrates them as chat acknowledgments, but any change to a user-owned workflow definition is submitted as a diff for operator validation, never applied silently; onboarding scaffolds a fresh workflow autonomously since nothing is overwritten. This reconciles ADR-0038 (self-evolve is operator-owned and opt-in) — genuine structural self-evolve stays opt-in via the diff while reversible knob-turning needs no human — and reuses ADR-0057's existing user-owned-workflow diff mechanism rather than inventing a new approval path. All Steward and Reflector output reaches the human only as messages in the unified first-person chat: validation items (clear on entity mutation, ADR-0048 intact) and acknowledgments (plain chat history, nothing to dismiss).
