# Chat runs on the Codex Responses API directly; daemon owns the tool loop and transcript

Context: chat threads ran on Codex CLI sessions (chat-runner: codex exec / exec resume, ADR-0080), so the CLI owned the agent loop, injected its own harness (base prompt, sandbox shell), and held the transcript in its session store — the daemon could not control what entered the context window. Decision: the chat runner now calls the ChatGPT-backend Codex Responses endpoint directly, authenticated with the OAuth token from ~/.codex/auth.json (refresh handled in-daemon, rotated tokens persisted back). The daemon replays the persisted thread transcript as input items on every turn (store:false — no server-side session; chat_threads.session_id and context_seeded are dropped), sends the Mars system prompt as the sole instructions, exposes one shell function tool, and executes tool calls itself. Trade-off: the endpoint is unofficial and may change without notice, and shell commands now run unsandboxed under the daemon; in exchange the context is fully daemon-owned, tool definitions are ours, and no Codex CLI binary is needed for chat. Supersedes the codex-exec clause of ADR-0080; thread/Bell semantics unchanged.
