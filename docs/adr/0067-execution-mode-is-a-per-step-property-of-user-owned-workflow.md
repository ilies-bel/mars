# Execution mode is a per-step property of user-owned workflows; workflow is a first-class task axis; no dispatch fallback (supersedes ADR-0066 live entry)

Context: ADR-0066's live entry (task add --live park-at-setup, proposal promote --live) bolted live execution onto dispatch as flags — promote --live broke promote's no-enqueue contract — and workflow iteration was blocked by the silent bundled-implementWorkflow fallback plus the ESM-cached import that ignores edits until daemon restart. Decision: who executes a step is declared per step in the user-owned workflow file (mode auto|manual; a manual step carries a Step guide and parks awaiting-human; mars step done completes it and the next manual park auto re-leases to the same owner). Which workflow runs is a first-class task field (--workflow, defaulting to kind; routing sessions choose from the available workflow set). A missing or invalid workflow hard-fails the task with the validator's error — the fallback is removed and imports are cache-busted so edits go live on the next dispatch. ADR-0066's Progress journal and attach-time Handoff stand; its park-at-setup and promote --live clauses are superseded (PRD live entry is one un-sliced task on a manual-heavy workflow). Trade-off: hard-fail trades resilience for honesty — a typo stops a task instead of silently running the fully-auto pipeline, which is why the single validation seam (mars workflow validate, reused by dispatch) is load-bearing.
