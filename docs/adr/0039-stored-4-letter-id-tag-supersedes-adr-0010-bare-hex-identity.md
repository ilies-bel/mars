# Stored 4-letter id tag supersedes ADR-0010 bare-hex identity

Mars ids become '<tag>-<hex>' with a fixed 4-letter kind tag (task, prop, orig, alrt, plus tags for every other id-bearing kind), and the FULL tagged string is the stored identity: primary keys, foreign keys, worktree directory names, and task/<id> branch names all carry the tag. This reverses ADR-0010 and the prior glossary stance, which made the bare hex canonical and the prefix render-only. No backfill or in-place migration: this is a hard cut — new-shape-only generators and parser (legacy mars-<hex>, bare-hex-as-primary, and reflect-<hex> branches deleted), with the state DBs reset to empty after the operator manually drains in-flight work and re-slices the kept proposals. Reset-from-empty sidesteps the live-worktree/branch rename hazard ADR-0010 warned about, since there is no in-flight work to orphan. The slug suffix on proposal ids is also removed; words live only in the title. Chosen because storing the tag lets the operator identify an entity's origin on sight (ls .mars/worktrees, git branch, raw DB rows), which render-only framing could not deliver.
