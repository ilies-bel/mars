# UI components speak semantic tokens only; Mars palette confined to stylesheet; dark theme removed

The ui/ codebase had two coexisting color vocabularies: raw Mars palette classes (text-iron x188, border-iron x199, bg-panel, ...) used directly in components, and a barely-used shadcn semantic layer, plus a dead .dark alias block nothing ever toggled. We decided components may reference only semantic tokens (primary, destructive, status-*, ...); palette tokens (iron, flame, dust, ...) live solely in index.css feeding the semantic aliases, enforced by a verify-time grep/lint gate. The dark theme is deleted outright rather than left half-shipped — re-adding it later costs only a second semantic mapping, which the semantic-only rule makes cheap. Trade-off: we give up direct palette expressiveness in components in exchange for homogeneity an agent fleet can be mechanically held to. The dark DAG canvas is a scoped design choice, not a theme, and stays.
