# pty-Runtime Session completion is a two-tier per-Provider signal: status-file handshake preferred, prompt-prefix-with-spinner-override scan as degraded fallback; no quiescence timer

Context: a headless 'claude -p' Session exits on its own when the prompt completes, giving the recovery loop a deterministic exit. A pty-Runtime Session runs the agent's INTERACTIVE harness, which idles at a prompt instead of exiting, so something must decide the turn is done and terminate the PTY. Decision: adopt ntm's (Dicklesworthstone/ntm) two-tier completion model, reused over Mars's node-pty transport rather than ntm's tmux: (1) PREFERRED — a status-file handshake: the agent writes a done-marker file (claude via a Stop-hook Mars controls) and the adapter treats that as authoritative; (2) FALLBACK — when the status file is absent/stale, scan the captured PTY output buffer for the Provider's prompt prefix WITH a spinner override (a visible prompt while the agent is still thinking is NOT idle). Each Provider adapter supplies its own prompt + spinner pattern; the status-file tier is provider-agnostic. claude gets the reliable status-file path; Providers without a hook mechanism (codex, gemini) ride the prompt-scan fallback as a deliberately-degraded tier until they grow a hook. Why not a bare quiescence/idle timer: ADR-0037 retired activity-based liveness precisely because threshold tuning produced false positives; the spinner-override prompt scan and the status-file handshake both avoid a tunable idle threshold. ntm's capture-pane maps to reading the node-pty buffer Mars already owns; ntm's send-keys maps to pty.write(); no tmux dependency is introduced.
