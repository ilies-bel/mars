# Steward health findings always enqueue; no direct-apply path

The Steward observes health but never mutates the codebase: every health finding it acts on becomes an enqueued task, routed through the ordinary code/verify/merge pipeline, even when the remediation is a single config value the Steward has already computed. Alternatives considered: a direct-apply path for cheap fixes (rejected — it creates a second, ungated way for Mars to change its own code, and the boundary between "cheap knob" and "structural edit" is not stable enough to encode), and a diff-for-validation path per ADR-0057 (rejected as redundant — enqueueing already produces a reviewable diff with a verify gate in front of it). This deliberately narrows ADR-0077, which grants the Steward autonomous runtime-knob turning: that grant stands for the Steward's own event classes (kpi-degraded, resource-load), but the doctor-registry health pathway has no direct-apply outcome at all. The cost accepted is real overhead — a whole task to change one value — bought in exchange for a single auditable path by which the framework modifies itself, with the merge gate as the backstop.
