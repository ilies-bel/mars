# Action queue is a pure projection of entity state; no operator close verbs, no dismissals table

Context: the resolve/dismiss/ack CLI verbs wrote only to action_queue_dismissals (via dismissEntity) and never to action_queue_items.state/history, while listActionQueueItems filters purely on state='open' — so an operator 'resolve' closed nothing and rows for purged entities orphaned (e.g. 36fdf42c). Decision: the action queue is a PURE PROJECTION of entity (task/worktree) state — a row exists iff its entity is stuck and leaves iff the entity transitions. There is no operator-facing gesture that closes a row. Hard cut: DELETE the resolve, dismiss, ack, and undismiss verbs and their CLI registration; DELETE the action_queue_dismissals table and all of dismissEntity/undismissEntity/isEntityDismissed/listDismissals/clearDismissalForEntity plus alert-dismisser.ts's calls into them; audit stale_worktree_dismissals as the same category error and cut it too. The Invalidator (alert-dismisser.ts) remains the sole row-closer, driven only by task.* / worktree bus events. Trade-off: we lose the 'operator hushes a failure' affordance and the deliberate ack-survives-restart behaviour (a restarted-then-re-failed task now re-raises a fresh row, which is correct under projection). Amends ADR-0041, which named the Invalidator 'the sole closer of Action-queue rows + dismissals' and treated dismissals as live; dismissals no longer exist. The orphan failure class is removed because the verb-and-table that produced it are gone, not because a missing purge-evict was added (queue.ts already emits task.terminal{purged}).
