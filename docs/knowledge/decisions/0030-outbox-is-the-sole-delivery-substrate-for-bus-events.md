# Outbox is the sole delivery substrate for Bus events

Context: today every state-mutating call site emits Bus events via in-memory bus.emit, which is at-most-once: a listener that isn't running when the event fires loses it forever. onBlockerTaskCompleted + recoverBlockedTasks patches one path (boot-time re-scan of blocker chains), but every other listener (Invalidators, recovery spawning, inbox raisers, transcript appends, idea lifecycle) has no recovery net. Decision: retire in-memory bus.emit as a delivery channel. Every Bus event is appended to a single outbox_events table in .mars/mars.db inside the same transaction as its triggering state mutation, owned by the TaskStore/StateStore seams per ADR-0021. Subscribers pull by cursor; in-memory internalBus survives only as a wake-hint nudge (commit-then-emit) with a 5s fallback poll for cross-process writes. Why: at-least-once delivery becomes a structural property (write happens or no state change happens) rather than a conventional one (call site must remember to also emit). Trade-off accepted: every state-mutating store method now writes two rows (state + outbox) in one tx, plus a small steady-state SQL load from cursor pulls; in exchange the staleness class that motivated this — daemon restart between commit and emit loses the event — is eliminated by construction.
