# Bell shows Alerts+Notices; chat shows only threads; alerts are no longer minted as chat threads

Context: raiseActionQueueItem currently fire-and-forgets maybeCreateAlertThread, minting a durable chat_threads row (origin='alert') for every action-queue raise; resolved ones only flip alert_resolved and pile into the chat History accordion, overwhelming the conversation list. Decision: split into two planes. The Bell (top-bar) renders the Action queue's alerts()+notices(); the chat sidebar renders conversation threads ONLY. Alerts never auto-convert to threads — a human pulls one into a thread (click a bell Alert, or a 'next action' shortcut that grabs the top-priority arc-root Alert, steerable). A thread carries an origin-arc back-reference; picking an Alert into a thread does NOT clear the Bell (ADR-0048 — the Alert clears only when its arc resolves). Threads run on Codex sessions (chat-runner: exec then exec resume) as an uncapped multiplexer with an attention-status (generating/ready/throttled/drafting), throttle and auth surfaced as status not per-thread errors; unengaged threads are pruned, engaged ones parked to History with their session id. Trade-off: reverses the merged-sidebar projection design and adds a Bell surface, but removes durable-thread churn and honors the pure-projection rule.
