# Idea->Task block edges allowed; Task->Idea still rejected

Amends ADR 0008. The planning graph (Ideas blocking Ideas in idea_dependencies) and the dispatch graph (Tasks blocking Tasks in task_blockers) remain separate, and Task->Idea edges remain rejected — a dispatched task must not wait on something that has not been promoted to a task. One cross-graph direction is now allowed: a Task may be blocked by an Idea, encoding 'this work is queued but cannot dispatch until that idea has been shaped and promoted.' These edges live in a third junction table, idea_task_blockers, with columns (task_id waits on idea_id); reusing task_blockers would force a polymorphic blocker_kind column and reintroduce exactly the disambiguation the original 0008 rejected. Lifecycle rules: on idea promotion the orchestrator atomically deletes the (task_id, idea_id) row from idea_task_blockers and inserts (task_id, new_blocker_task_id) into task_blockers in the same transaction, so no dispatcher tick can observe a task with zero blockers between the two writes; on idea dismissal the dismiss is refused while any row in idea_task_blockers references that idea, surfacing the dependents to the user so they explicitly redirect or drop them. The 'separate junctions per graph' principle from 0008 is preserved — three narrow tables with fixed endpoint types, not one polymorphic table — so every reader still knows its endpoints by table name and no kind discriminator is needed.
