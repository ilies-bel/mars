# Slice verticality is verified after merge by the arc-verifier, not gated at slice time

The CLI promises 'vertical-slice tasks' and the glossary defines sliced as decomposition into tracer-bullet tasks, but nothing enforced either: PRD ecf4b8ee produced 7 slices touching only api.ts and db.ts, shipping a feature no human could reach. We considered a slice-time gate on the emitted plan (SliceSpec already declares modifies/creates) and a pre-merge block in the per-task review step. We chose neither. Per-task review cannot hold the invariant because slices 1..N-1 of a correct vertical PRD legitimately touch no surface, and a plan-time gate judges a prediction rather than the result. The arc-verifier already fires at arc-done, already spot-checks done criteria against the merged diff, and already escalates one action-queue item per originId — so verticality becomes one more class of finding there. The accepted cost is that the gap is caught after the code is on the integration branch: this reports, it does not block.
