# Operator control levers are unified under one persisted surface; supersedes set-flag ephemerality

Context: the operator's token/dispatch levers were scattered across in-memory feature toggles, persisted spend configuration, MARS_* env vars, and daemon.json fields — with no single place to read current state, and no lever to stop auto-reflect spend short of the blunt MARS_REFLECT_DISABLED which also kills signal capture. Decision: introduce one 'mars operator' surface (operator status reads every lever's live+configured state, operator set flips any lever) and make ALL levers persisted daemon.json control levers, applied config->live-env on daemon startup and on each set. This replaces the old ephemeral controls and consolidates command groups in a hard cut. Why: a daily token-budget operator needs durable week-long holds (set once, survives restart), and one mental model — every lever is a daemon.json field — beats two opposite durability models under one verb. Trade-off accepted: we lose the incident-response 'auto-clears on restart' safety for the three kill-switches; the operator re-enables them explicitly when a storm passes.
