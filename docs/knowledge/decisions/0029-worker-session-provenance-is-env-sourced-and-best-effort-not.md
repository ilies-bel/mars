# Worker-Session provenance is env-sourced and best-effort, not spoof-proof

When a dispatched Worker Session invokes a mars verb, the (Worker, Session, Author) provenance triple is read off the child process env (MARS_WORKER / MARS_SESSION_ID) the Worker injects at spawn and stamped by the daemon onto a verb-invocation audit event. A dispatched Session can spoof or strip these env vars; we deliberately do not make provenance tamper-proof. Trade-off: the threat model is accidental scope drift and post-hoc audit of the honest case, not defence against a hostile Session (which already runs under --dangerously-skip-permissions in its own worktree and could do far worse). Spoof-proof provenance would require the daemon to correlate each inbound call to a live dispatched Session via an unforgeable token — a separate, larger project that contradicts the consolidation framing of this work.
