# Retire activity-based liveness from ADR-0036; ship run-to-natural-completion plus Spawn governor instead

ADR-0036 codified a coupled design — activity-based liveness (Stale-then-Dead state machine aborting workers via exit 125, with a worker-stale ErrorKind under failed-task) plus a Spawn governor (load-and-memory admission control in front of acquire(sems.<kind>)). The proposal it codified (71942f04) shipped a different design: every Worker runs to natural completion (no wall-clock kill, no message cap, the only termination paths are child-exits / mars daemon kill / mars restart) plus the same Spawn governor. The activity-watchdog half is retired — its complexity (10-sec ticker walking TaskFlightTracker, in-memory lastOutputAt bumped from runClaudeCode's stream callback, worker.stale/worker.dead Outbox transitions, Subscribers stamping a new failure signature, a new ErrorKind, a new exit code) all served a failure mode the run-to-natural-completion rule eliminates instead of catching. Removed glossary terms: Stale worker, Dead worker. Retained glossary terms: Spawn governor, Pressure level (the governor half ships unchanged). The mars daemon kill path is left to ADR-0035's daemon-killed ErrorKind — operator-initiated kills already surface in the inbox with restart actions; no new ErrorKind needed for this PRD. Cost: 71942f04 leaves the genuinely-wedged-worker case (a process that hasn't exited but is no longer making real progress) as the operator's problem, cleared by mars daemon kill — no daemon-side detection, no automatic recovery. This is deliberate; the previous activity-watchdog design's threshold tuning was a bigger source of false positives than the wedge case was a source of stuck-task pain.
