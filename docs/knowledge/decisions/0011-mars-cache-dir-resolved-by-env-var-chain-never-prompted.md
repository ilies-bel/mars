# Mars cache dir resolved by env-var chain, never prompted

Context: mars install and mars update download Bundle tarballs into a per-host cache. The first-install wizard could prompt for a cache directory when the default isn't writable. Decision: resolve the cache directory by a fixed chain — $MARS_CACHE_DIR, then $XDG_CACHE_HOME/mars-framework, then ~/.cache/mars-framework. Never prompt interactively. If the resolved path is not writable, fail with a one-line message naming the env var to set (e.g. 'error: cache dir <path> is not writable. Set $MARS_CACHE_DIR to an alternate path.'). Why: interactive path entry is a usability anti-pattern (free-form TTY input is fiddly, defaults through 95% of the time, can't be answered in CI). Following XDG Base Directory Spec matches what cargo, pip, npm, gh, bun, uv, rustup, pnpm, helm, and kubectl all do. The env-var escape hatch is scriptable and persistable without inventing a 'mars config' subsystem. Cost: the chain becomes a public contract; consumers scripting around the cache path can rely on these three env vars in this order.
