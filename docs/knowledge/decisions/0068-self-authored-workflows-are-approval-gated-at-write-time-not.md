# Self-authored workflows are approval-gated at write time, not runtime-sandboxed

Context: an agent can author a plain-JS pipeline into .mars/workflows/, but validateWorkflow executes the author's fn, so the runtime is not a safe trust boundary. Decision: agent-authored workflows whose bodies pass `lintAgentWorkflowBody` (`workflow-lint.ts`) — importing only from `mars/workflow`, binding only `defineWorkflow` and primitives with an `exportName` (`setupWorktree`, `runAgent`, `review`, `merge`, `awaitHuman`), no `require`/`eval`/`Function`/`process`/`globalThis`, no top-level side effects outside imports and the default export — are auto-approved at write time via `stampAutoApproved` (no `pending-approval` marker, no action-queue review item). Bodies that fail lint are rejected entirely at author time; there is no 'land as draft and gate' path. Agents may add new pipelines but never overwrite or rewire task/fix/live. Trade-off: we accept that the lint surface (`workflow-lint.ts`) is the trust boundary for primitive-only bodies — execution privilege is gated by static-analysis proof rather than operator review, eliminating the autonomy cost for the common case while preserving the security invariant (no unreviewed arbitrary JS at daemon privilege).
