# Test suite uses a per-fork hermetic MARS_REPO to prevent live-state bleed

Context: the orchestrator resolves its repo root (and all derived paths — `.mars/daemon.json`, `.mars/pg.dsn`) by walking CWD upward via `git rev-parse --git-common-dir`. A worker fork spawned by Vitest inside a task worktree (`.mars/worktrees/<id>/`) correctly escapes back to the real repo root, so `loadDaemonConfig()` reads the live `.mars/daemon.json` and the live `.mars/pg.dsn` unless overridden. A running daemon that persists an autotune cap (e.g. `caps.verify: 2`) to `daemon.json` silently overwrites any `MARS_MAX_*` env value a test sets; a running daemon that inserts rows into the live embedded-postgres moves rows under in-flight test assertions. Both effects produce non-deterministic test failures that are impossible to distinguish from real code defects (observed: `getTestDb > gives a later test setup an empty database` and 2404 failures while the daemon was active, vs the same suite passing when host state was quiet). Decision: `test/setup-env.ts` unconditionally sets `MARS_REPO` to a private `mkdtemp`-created directory (unique per worker-fork PID) before any test file loads. `resolveContext()` reads `MARS_REPO` as its first override, so every derived path — config file, database target key — lands inside the throwaway temp dir. `MARS_DB_BACKEND=pglite` (also unconditional in the same file) redirects database access to an in-process, in-memory PGlite backend, bypassing the embedded-postgres server entirely. A `beforeEach` guard asserts after every test that `MARS_REPO` (if set) does not point back at the real `.mars`, so a test that accidentally resets the variable produces a loud, actionable failure rather than 2404 mysterious assertion errors. Trade-off: tests can no longer rely on an inherited shell's `MARS_REPO` or `MARS_DB_BACKEND`; developers who need to exercise specific paths must override them explicitly inside the test with a `try/finally` restore. This is an acceptable constraint because hermetic isolation is the correct default for a deterministic test suite, and explicit overrides are always possible.
