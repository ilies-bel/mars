# Behaviour verification distinguishes FAIL from CAN'T-VERIFY; only FAIL blocks

Context: a pre-merge behaviour-verify step drives Playwright MCP against a live surface to check Definition-of-Done criteria. A naive gate would wedge merges whenever the surface is unavailable. Decision: three outcomes. PASS proceeds to merge. A behavioural FAIL (positive evidence of contradiction on a reached live surface, with a per-criterion verdict + screenshot) spawns exactly one recovery Chore on the origin worktree. CAN'T-VERIFY (no runnable surface, absent/ambiguous DoD, dev-server won't boot, MCP unavailable, unparseable verdict) degrades to a fingerprint-deduped draft proposal + a level-triggered action-queue alert, then merge proceeds. It never silently passes and never hard-fails for un-verifiability. Trade-off: environmental flake can never wedge a fix's own merge (defusing the circular-wedge), at the cost of letting un-verifiable work merge with an operator alert rather than blocking it.
