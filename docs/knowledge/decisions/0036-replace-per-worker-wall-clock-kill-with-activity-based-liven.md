# Replace per-Worker wall-clock kill with activity-based liveness and gate Worker spawns behind a Spawn governor

Per-Worker wall-clock kills in runClaudeCode (Coder/Fixer 20min, Planner/Slicer 5min, Triager 2min) killed slow-but-progressing workers under load; the box also had no admission control, allowing dispatch storms past sustainable system pressure. Replaced both with a single daemon-level mechanism: a 10s ticker that (a) walks TaskFlightTracker entries, comparing in-memory lastOutputAt against per-Worker Stale and Dead thresholds and emitting worker.stale / worker.dead Outbox transitions; a worker.dead Subscriber stamps failureSignature 'worker-stale', aborts via the existing AbortController (new exit code 125), and the resulting failed task surfaces through a new worker-stale ErrorKind under the failed-task rowKind (mirroring daemon-killed), with {Investigate, Restart, Purge} actions and no auto-recovery; (b) reads loadavg/cpu-count and memory-used at the same tick, computing a Pressure level (Normal/Elevated/High/Critical) that the Spawn governor consults before acquire(sems.<kind>); High and Critical refuse spawns, leaving the task queued for the next drain. Structured-write is exempt from the governor to avoid self-induced deadlock. Rejected alternatives: in-process watchdog inside runClaudeCode (two mechanisms needed for governor anyway); load-only sampling (misses memory pressure); per-stage carve-outs beyond structured-write (priority inversion); auto-recovery on worker-stale (the whole point is operator-decided); full reactive outbox per stream-line (volume cost on the durable substrate); a separate worker-stale rowKind (failed-task fan-out follows the daemon-killed precedent from ADR-0035). Hard cut: no MARS_USE_WALLCLOCK_KILL flag, no migration window. installWorktreeDeps and worktree-clean keep wall-clock kills (not claude -p workers, no heartbeat-shaped output).
